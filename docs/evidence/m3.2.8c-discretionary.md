# M3.2.8c — discretionary lane changes (D95) and the hold (D101): A53 evidence

**Not validated.** Development evidence on an unvalidated, Wiedemann-inspired prototype. Windows
11, MSVC Release, 2026-10-02. Every run is `trafficsim-lane-change-sweep`, which sets the D95
fields (and, with `--hold`, D101's) on the compiled scenario; `acceptedDecelerationTrailingVehicle`
is 1 m/s² throughout. No shipped behaviour carries these fields: D95 stays **off**.

A53 as D101 rewrote it: a discretionary change straight back to the route the vehicle's previous
change left, within 10 s of it, is a **return**. D95 passes when returns are at most **1%** of
discretionary changes (the cap proposed 2026-10-02).

## Why (D101 step 1, PROGRESS "Why D95's changes reverse")

The incentive compares one tick of `followingAcceleration`, which has hard regime edges
(`speedThreshold`; the approach horizon), and it sees only the nearest vehicle ahead, so a leader
still braking into its queue looks better than a standing one. The hold cannot touch either: it
delays the next decision, it does not change what the decision compares.
